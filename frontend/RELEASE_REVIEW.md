## 本次发现与修复

- npm 首轮扫描发现 13 项告警（5 高、7 中、1 低），包含开发/构建依赖；在既有版本约束内更新锁文件后为 0 项。Vite 升至 7.3.8。该结果只代表本次 npm 公告库扫描，不涵盖 Go、操作系统、镜像全部组件或未知漏洞。
- 请求增加 JSON 30 秒、分片/文件 120 秒、刷新 10 秒的截止时间，包含响应体读取。临时网络/服务端错误不再误删续期凭据；迟到的 401 复用已刷新的令牌，避免重复刷新；退出后的响应不能恢复登录。
- 切换视频/会话后，旧请求不再清空新草稿或改变新请求的发送状态。资料加载失败时禁止提交，头像校验先于账号改名。关注列表加载失败时允许重试，不猜测关注状态。
- 退出接口不可用时仍清理当前设备的令牌，并提示服务器注销未完成。**本地清理不能保证服务端令牌已撤销。**
- 新增浏览器私信用例发现滚动 API 返回值被误用为 React 副作用清理函数，导致页面崩溃；改为明确不返回值的副作用。测试覆盖中文输入法、换行、失败保留草稿及重试。
- Nginx 运行时从 1.27 更新至 1.30.7-alpine；增加 CSP、nosniff、禁止嵌入、无 Referrer 和权限策略，隐藏版本号。CSP 禁止内联脚本和非同源连接；为兼容 Radix 行内样式保留 `style-src 'unsafe-inline'`，为兼容既有媒体 URL 保留 http/https 图片与媒体来源。它不是完整的 XSS 防护或媒体域名白名单。
- HTML 和 API 响应禁止缓存，带指纹的构建资源长期缓存；不存在的构建文件返回 404。对普通、错误、API 和静态响应验证安全头继承。
- CI 增加 `server_test` 推送触发、依赖扫描和真实 Nginx 镜像的 Chromium/WebKit 全流程回归。实际执行 CSP 阻断与文本注入测试，检查页面行为没有违反策略。

## 后续直连 OSS 的实现边界

现有 `src/react/upload.ts` 与发布页面分离；后续可增加 OSS 上传适配层，在未启用直传配置的环境中沿用本地上传。不要将应用 API 请求客户端直接复用于 OSS，以免携带应用 Bearer 凭据。

1. 后端在鉴权和配额检查后签发短期 STS 或预签名上传信息，限定用户对象前缀、权限、有效期、大小与类型。长期 AccessKey 仅在服务端或云角色中保存，绝不放入 `VITE_*`、仓库或浏览器包。
2. OSS CORS 只允许正式站点及确有需要的预览站点、方法和请求头，暴露分片所需的 ETag。CSP 的 `connect-src` 按实际 Bucket/CDN 精确放行，不为将来的能力预先添加任意域名。
3. 浏览器使用独立 OSS SDK/客户端实现分片、重试、续传、取消和过期凭据恢复；上传完成后由后端校验对象归属、大小、校验信息和发布权限，再登记作品。客户端声称上传成功不能作为信任依据。
4. Bucket 权限、对象公开范围、签名播放/CDN、Range、跨域与缓存必须一起设计；视频、封面、头像分别制定可访问策略。压测、删除和孤立分片清理需要测试。

参考：[阿里云 OSS 客户端上传](https://help.aliyun.com/en/oss/user-guide/uploading-objects-to-oss-directly-from-clients/)、[OSS 授权方式](https://help.aliyun.com/en/oss/developer-reference/authorize-access-6)。本次没有启用 OSS 直传。

## 部署、回滚和继续开发

- React 默认构建入口已经切换；`npm ci && npm run build` 输出 `frontend/dist`，生产通过 `frontend/Dockerfile` 构建 Nginx 镜像。同源 `/api` 与 `/static` 代理到 Compose 内部的 `backend:8080`。`API_PROXY_TARGET` 只用于本地 Vite，不用于改变生产 Nginx 上游。
- 在干净、确认过提交 SHA 的工作树构建镜像，记录并保存镜像 digest；不要直接从存在未提交部署/OSS 草稿的主目录构建。先预发布验证，再部署；发布期间保留上一版带指纹的 JS/CSS，避免已打开页面的懒加载请求遇到旧文件被删除。
- 回滚前端优先切回前一镜像；本次没有数据库迁移。需要撤销合并代码时，对合并提交使用 `git revert -m 1 <merge-sha>`，验证后走正常推送，避免重写共享分支历史。
- 主工作区的未提交草稿保持原样，其本地 `server_test` 不会被强制重置。远程合并后不要在该目录盲目拉取或覆盖；后续 React/OSS 开发应从最新的 `origin/main` 创建干净分支，逐项迁移并测试草稿，PR 指向 `main`。
