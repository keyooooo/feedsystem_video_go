# GikGok 视频详情与用户主页优化

基线为 `main` 的 `8e65243`。本文描述视频详情、共享播放器和用户主页的开发范围及验收标准。

## 1. 视频详情页与首页共享播放器

`/video/:id` 使用首页现有的播放器展示模式，复用视频画面、底部控制条、简介层和右侧互动栏。首页继续负责 Feed 滚动、虚拟化、分页和切片。详情页保留独立链接、单视频加载和错误重试。

- 从 `VideoPages.tsx` 提取首页已经在用的播放器展示组件。首页和详情页共同使用比例判定、封面模糊背景、进度条、播放暂停、静音、全屏和 OSS 播放地址续期。竖屏保持原比例居中，方形保持方形，横屏在可用区域横向铺开。封面缺失时使用播放器的深色底。
- 发布者头像、点赞、评论、分享依次排列在播放器内。点击头像或作者名进入 `/u/:id`。详情页原有的关注按钮由作者头像入口替代，关注可在用户主页操作。简介区保持透明，详情页作品标题为 `h1`，首页标题仍链接到详情页。
- 继续使用现有评论组件。宽屏详情默认打开右侧评论栏，关闭后播放器取回可用宽度。窄屏通过评论按钮主动打开弹层。评论栏切换时保留视频播放进度与静音状态。
- 保留现有分享链接、剪贴板失败后的手动复制、浏览器自动播放限制和签名续播逻辑。标题或简介过长时允许收敛，保持互动栏及控制条可见。

### 互动按钮尺寸

下表为 CSS 像素起点。桌面与移动端均适用首页和详情页。分别在 1440、768、390、360px 视口检查后微调。

| 项目 | 桌面 | 窄屏 |
|---|---:|---:|
| 发布者头像直径 | 52px | 46px |
| 点赞、评论、分享图标 | 28px | 24px |
| 每个按钮的最小触达区 | 52 × 52px | 44 × 44px |
| 互动栏纵向间距 | 10–12px | 6–8px |

图标使用项目现有线性样式，按钮背景保持透明。已赞统一用 `--liked` 珊瑚红实心，未赞用浅色描边。点赞数单独显示。通过对比度、轻微描边或阴影保证亮画面上的可读性。按钮保留可见的键盘焦点、无障碍名称和点赞的 `aria-pressed`。

## 2. 用户主页采用已确认的预览

- `/u/:id` 和自己的 `/account` 共用主页布局。头像、用户名、简介和统计对齐为紧凑资料区。使用真实简介，空简介时省略这一行。作品、获赞、粉丝、关注统一为横向统计，粉丝与关注保留列表入口。
- 他人主页保留「关注」主按钮和「私信」次按钮。自己的主页保留「编辑资料」。公开主页展示「作品」，自己的主页展示「作品」「喜欢」。当前标签使用细珊瑚色下划线。
- 使用 4:5 封面和独立标题行，作品少时卡片仍按网格列宽排列。桌面默认四列，按容器宽度降为三列或两列。公开作品页省去重复作者名，自己的「喜欢」卡片可保留作品作者。封面缺失或加载失败时显示同尺寸的深色占位。
- 卡片左下角以同一套心形图标显示当前访问者的已赞状态及作品总赞数。红心表示当前登录用户已赞，空心表示未赞。整张卡片链接到视频详情，封面心形是状态标识。登录者看自己的「喜欢」时，每张卡片都显示红心。

## 3. 点赞状态与 API

首页 Feed 已返回 `is_liked`。详情页保留 `/video/getDetail` 和登录后的 `/like/isLiked`，通过共享互动栏渲染结果。访客可浏览，点赞沿用登录引导。读取状态失败时保留可播放的详情，同时提供重试，避免把未知状态当作未赞并发送错误的操作。

当前作者作品接口 `/video/listByAuthorID` 返回视频实体，缺少访问者点赞字段。`/like/listMyLikedVideos` 最多返回最近 200 条，无法完整判断公开主页上较早的作品是否已赞。为作品列表补充向后兼容的可选 `is_liked` 字段，沿用路由和数组结构。由现有软鉴权识别访问者，通过一次批量查询按本次作品 ID 求点赞状态。访客按未赞展示，旧客户端可继续读取原字段。自己的「喜欢」沿用原接口和当前数量上限。

首页和详情使用同一套点赞交互与请求。`/like/like` 或 `/like/unlike` 成功后同步更新当前画面的红心和计数，并让同一登录会话内切页后仍能看到刚完成的操作。现有后端可能异步落库，前端按会话和视频 ID 暂存已确认的操作，阻止旧响应立即覆盖结果，在后续读取与操作结果一致时交还给服务端数据。暂存需有失效边界，切换账号或退出时清理。请求失败时保留上一次确认的状态，计数不会重复加减或小于零。

## 4. 开发顺序

1. 复用首页展示组件替换详情旧布局，统一互动栏和点赞表现。检查首页的切片、键盘导航和评论布局。
2. 更新主页资料区和作品卡片，为作者作品补充访问者点赞状态。验证首页、详情和主页之间的状态传递。
3. 运行前端 lint、类型检查、单测、生产构建、Chromium 和 WebKit 回归。为作品接口的访客、已赞用户和另一账号补充后端用例，并按仓库流程提 PR、检查 CI，在预发布验收。

## 5. 验收场景

- 首页点赞某个视频，打开详情显示同一颗红心；详情取消后，返回首页或进入作者主页，该视频恢复空心。刷新后以服务端状态为准。模拟写入延迟、接口失败和换账号，检查计数与状态。
- 用拥有超过 200 个点赞的账号打开作者主页，较早点赞的作品仍显示红心。用另一账号或访客打开同一作品卡，验证红心属于当前访问者。
- 首页与详情分别测试竖屏、方屏和横屏。详情打开或关闭评论后播放不重置；评论弹层、作者链接、分享、静音、全屏与 OSS 签名续播可用。
- 在桌面和 360–390px 手机尺寸检查大一号的按钮、长昵称或标题、缺失封面、空作品列表、低高度视口和键盘操作。互动栏、评论栏和底部控制条之间无重叠或横向溢出。
